## 它能做什么

Mail Agent 只做一件事：**从你已经收到的邮件里追踪整个求职进程。** 它提供三个界面：

| 界面 | 你能得到什么 |
| --- | --- |
| **求职看板 · Job board** | 每一次投递的看板／公司视图。Claude 阅读你的邮件，提取*公司 · 职位 · 投递日期 · 状态*，按公司归并重复邮件，并给出统计面板（漏斗图、状态环形图、投递趋势）。状态只会向前推进 —— 你手动修改的状态具有最高权威，不会被后来的邮件悄悄降级。 |
| **收件箱 · Inbox** | 分页邮件阅读器（每页最新 100 封）。打开任意邮件即可安全阅读，并一键把非英文邮件**翻译**成英文（或中文、日文、韩文、法文、德文、西班牙文）。 |
| **设置 · Settings** | 连接一个或多个邮箱、粘贴模型 API Key、为不同任务选择模型、调整提取提示词，并选择翻译语言。 |

## 为什么你的数据是私密的

Mail Agent 分为两部分：

- 一个**网站**（上面那些界面），已经为你托管在
  <https://mail-agent.vercel.app/>。它只是界面 —— 本身不存储任何东西。
- 一个小小的**后端**，**运行在你自己的电脑上**。它保存你的邮箱连接、本地数据库和 API
  Key，并完成所有的同步与提取工作。

网站**只与你自己电脑上的后端**（`http://127.0.0.1:8765`）通信。你的邮件和密码不会传到任何
共享服务器 —— 无需注册，也不用创建账号。你的 IMAP 授权码和 API Key 会加密保存在你的电脑上，
绝不会写入数据库，也不会分享到任何地方。

## 三步开始使用

**1 · 安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)**（免费）。
它负责在你电脑上运行那个小后端。

**2 · 启动后端。** 打开一个终端，运行：

```bash
docker run -d --name mailagent -p 127.0.0.1:8765:8765 \
  -v mailagent-data:/data \
  ghcr.io/54younger/mail-agent:latest
```

整条命令就是这样 —— 没有需要你填写的参数。它会下载后端、启动它，并把你的数据保存在
`mailagent-data` 卷里，重启和升级都不会丢。

**3 · 打开应用：<https://mail-agent.vercel.app/>**

网站会自动连接到你电脑上的后端。如果你在后端就绪前就打开了它，页面会显示一个简短的
「请启动后端」提示，并在容器运行后自动连上。随后按照[首次设置](#在应用内完成首次设置)操作。

> **支持哪些浏览器？** 请使用 **Chrome、Edge 或 Firefox**。不支持 Safari（它会阻止安全网站
> 访问你本地的后端）。

之后要停止后端：`docker stop mailagent`；再次启动：`docker start mailagent`；升级：先
`docker pull ghcr.io/54younger/mail-agent:latest`，再删除并重新运行容器（卷里的数据会保留）。

## 在应用内完成首次设置

应用加载后，请**按顺序**完成以下步骤。全部在浏览器里进行 —— 无需编辑任何配置文件。

**1 · 连接邮箱** —— 进入 **设置 · Settings → 绑定账户**
- 选择你的服务商（Gmail、Outlook、QQ、163、126），或选 **其他** 填自定义 IMAP 服务器。
- 填写你的**邮箱地址**和一个**应用专用授权码** —— 这是你在邮箱安全设置里生成的一串码，
  **不是**你平时的登录密码（见[邮箱服务商](#邮箱服务商与凭据)）。
- 服务器地址和端口会自动填好（加密 IMAP，端口 `993`）。
- 保存后即连接邮箱并开始首次同步。你可以连接多个邮箱。

**2 · 填入模型 API Key** —— 仍在 **设置 · Settings** 中
- 最简单：粘贴一个 **Claude API Key**，默认会用于全部任务。
- 进阶：为每个任务单独配置（见下一步）。

**3 ·（可选）为每个任务选择模型**
后端使用三个独立角色，每个都有自己的模型和 Key：

| 任务 | 默认模型 | 用途 |
| --- | --- | --- |
| `extract` | `claude-sonnet-5` | 阅读邮件并提取求职投递记录 |
| `translate` | `claude-haiku-4-5` | 翻译邮件正文 |
| `classify` | `claude-haiku-4-5` | 轻量分类 |

每个任务都可以通过设置自定义的 base URL、模型名和 Key，指向 **Claude** 或任意**兼容
OpenAI** 的服务（DeepSeek、Together、本地 Ollama……）—— 提取提示词也可编辑，方便你调优。

**4 ·（可选）设置翻译语言**
默认是**英文**。你可以切换为中文、日文、韩文、法文、德文或西班牙文。

**5 · 提取** —— 打开 **求职看板 · Job board** 并点击**提取**。Claude 会阅读已同步的邮件
并填充看板。新邮件到达后可随时再次运行；你手动修改的内容始终优先。

> **界面语言：** 界面**默认英文**，可通过侧边栏底部的切换按钮切换为**中文** —— 这与上面的
> 邮件翻译语言相互独立。

## 日常使用

- **求职看板 · Job board** —— 展示各公司及其当前阶段、统计面板（漏斗 / 状态环形图 / 趋势），
  以及每条投递记录的抽屉视图（含状态时间线）。手动修改状态后即成为权威值。
- **收件箱 · Inbox** —— 按最新在前浏览，每页 100 封；打开邮件即可阅读，点击**翻译**可得到
  译成所选语言的清晰译文。
- **同步** —— 同步栏可按需拉取新邮件（增量或全量重新同步）；后台同步会自动持续拉取新邮件。

## 邮箱服务商与凭据

163 / QQ / 126 / Gmail / Outlook 等绝大多数服务商都要求使用**应用专用授权码**（而非登录
密码），并在邮箱的网页设置里**开启 IMAP**。请在邮件服务商的安全设置里生成该授权码，并把
*它*填进连接表单。若连接失败，向导会给出针对你所用服务商的指引（例如 163 的 IMAP 安全验证
步骤）。

## 想把整套都跑在自己电脑上？

你也可以不用托管网站，把整套（界面 + 后端）都跑在本地。先克隆仓库：

```bash
git clone https://github.com/54younger/mail_agent.git
cd mail_agent
```

然后任选其一：

**Docker Compose（单容器，在 `http://127.0.0.1:8765` 上提供全部内容）**

```bash
docker compose up --build          # 然后打开 http://127.0.0.1:8765
```

**一条命令，无需 Docker**（先构建界面，再启动后端并提供该界面）：

```bash
./start.sh                         # 然后打开 http://127.0.0.1:8765
```

**带热重载的开发模式（两个终端）：**

```bash
# 终端 1 —— 后端  http://127.0.0.1:8765
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
python run.py

# 终端 2 —— 界面  http://localhost:5173
cd frontend
pnpm install
pnpm dev
```

这些本地方式的要求：Python 3.11+，以及（非 Docker 方式还需）Node 18+ 和 `pnpm` 或 `npm`。
任何一种方式下，后端都只绑定 `127.0.0.1`，因此绝不会从公网被访问到。

## 故障排查

- **应用显示「请启动后端」** —— 你的 Docker 容器没在运行。启动它
  （`docker start mailagent`），页面会自动重新连接。
- **端口 8765 提示 `address already in use`** —— 端口已被占用。停掉旧后端：
  `docker stop mailagent`，或在本地运行时用 `lsof -ti :8765 | xargs kill -9`，然后重新启动。
- **Safari 无法连接** —— 属预期现象；Safari 会阻止安全网站访问你本地的后端。请使用 Chrome、
  Edge 或 Firefox。
- **连接邮箱失败** —— 几乎可以肯定是你用了登录密码而非**应用专用授权码**，或者邮箱设置里
  未开启 IMAP。

## 配置项参考

几乎所有设置都在应用内完成。以下环境变量是为上面的本地自托管方式准备的：

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `MAIL_AGENT_HOST` | `127.0.0.1` | 后端绑定地址（Docker 内为 `0.0.0.0`） |
| `MAIL_AGENT_PORT` | `8765` | 后端端口 |
| `MAIL_AGENT_DATA_DIR` | —— | 预设数据文件夹（跳过首次的文件夹提示） |
| `MAIL_AGENT_CORS_ORIGINS` | `https://mail-agent.vercel.app`（Docker） | 允许调用你后端的网站来源 |

界面基于 Vite + React + TypeScript；后端基于 FastAPI + SQLAlchemy + SQLite + imap-tools +
Claude。此前的 Flutter 桌面版已归档在 [`legacy/`](legacy/) 目录下。路线图见 [`PLAN.md`](PLAN.md)。
